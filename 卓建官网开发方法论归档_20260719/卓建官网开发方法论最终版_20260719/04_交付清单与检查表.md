# 交付清单与检查表

这是一页式主清单的展开版。项目负责人可打印使用，也可复制到任务管理工具。每一项应填写负责人、证据链接和状态；“口头确认”“应该没问题”不算完成。

## 一、需求与边界

- [ ] 已列所有页面、栏目、列表、详情、静态页和特殊入口。
- [ ] 已列桌面、移动端、后台、中文、英文的范围。
- [ ] 已写明确不做项和延期项。
- [ ] 每个需求有用户可观察的验收结果。
- [ ] 相似术语已映射到正式对象，如“管理员”对应真实 role。
- [ ] 小补丁有 changed-files 和业务 allowlist。
- [ ] 发现第三类变化时有暂停和重新决策机制。

## 二、页面字段消费矩阵

- [ ] 每个字段有录入者、存储位置、API、显示位置。
- [ ] 每个字段说明列表/详情/首页资源位消费者。
- [ ] 每个字段说明排序、筛选、关系和语言映射用途。
- [ ] 空值、旧数据、删除和 fallback 行为明确。
- [ ] 无消费者字段不进入后台。
- [ ] 从 admin/API 移除与物理删列分开决策。
- [ ] 旧契约已与当前源码对照，不照抄过时字段。

## 三、内容模型与发布

- [ ] Global 与 Collection 的选择有理由。
- [ ] slug、ID、sourceRecordId、sourceRoute 各自职责明确。
- [ ] 草稿、发布、版本历史和发布时间语义明确。
- [ ] 匿名只读取 published；draft 的 REST/Local API 都受控。
- [ ] 保存草稿、立即发布、发布修改已测。
- [ ] schedulePublish 是否启用有明确业务决定。
- [ ] `publishedAt` 不覆盖置顶、资源位、featured 和显式排序。

## 四、角色与权限

- [ ] 所有正式 role 逐行列出，不用口语代替。
- [ ] 后台导航可见性已测。
- [ ] 按钮、表单和字段可见性已测。
- [ ] REST、Local API、Collection access 已测。
- [ ] private 文件读取/下载/删除已测。
- [ ] UI 隐藏之外有服务端 ACL。
- [ ] 停用、删除账号后的旧会话已测。
- [ ] 用户查询异常按 fail closed 处理。
- [ ] 内部 hook 权限不扩大角色直接权限。
- [ ] 最后一个最高权限账号有保护。

## 五、媒体、富文本与关系

- [ ] 公开媒体和 private 附件物理隔离。
- [ ] 类型、大小、尺寸、alt 和复用规则明确。
- [ ] 素材先入素材中心，再由内容关联。
- [ ] media 代理拒绝路径穿越和 private 路径。
- [ ] 富文本节点、链接、列表、图片和空节点可稳定渲染。
- [ ] 关系从 CMS 到 BFF、display-data、view 全链路保留。
- [ ] 删除目标、共享附件和孤立清理行为明确。
- [ ] private 内容不进入快照、Git、日志和公开响应。

## 六、双语与 provenance

- [ ] 来源权威明确，切换前重新读取最新生产来源。
- [ ] record hash、field path、source text hash 可追溯。
- [ ] source unavailable/stale 在任何写入前失败。
- [ ] importer 单批事务，第 N 条失败全回滚。
- [ ] 相同输入重跑零 create/update/version/updatedAt。
- [ ] 关系 target 和媒体都有映射。
- [ ] 无中文 fallback，汉字泄漏扫描通过。
- [ ] sourceRecordId/sourceRoute 同页切换通过。
- [ ] 缺英文对应内容按规则回 locale 首页。
- [ ] snapshot、静态媒体和 release manifest 哈希一致。
- [ ] 内容发布产物不被普通 prebuild 隐式重写；若当前仍有风险，列为 P2。

## 七、SQLite、迁移与运行资产

- [ ] 源码、SQLite、public media、private、env、备份分开管理。
- [ ] 生产 SQLite/public/private/env 是运行权威，不被本地覆盖。
- [ ] schema 变化使用显式 migration，不依赖隐式 push。
- [ ] migration 在生产数据副本演练。
- [ ] quick_check 和 FK 检查通过。
- [ ] 历史字段隐藏与 drop column 分开。
- [ ] 即时完整备份可恢复。
- [ ] 并发业务写入在切换中被识别和保留。
- [ ] env 值、数据库记录和 private 内容不进入证据包。

## 八、公开写接口与安全

- [ ] 尽量使用专用 route，不开放匿名通用 Collection create。
- [ ] Content-Length 声明超限在解析前拒绝。
- [ ] 无长度/chunked 实际超限在完整缓冲前拒绝。
- [ ] Content-Type、字段、文件类型和大小有限制。
- [ ] 反向代理链只读确认，不信任伪造 XFF 第一项。
- [ ] 前端代理不透传客户端伪造代理头。
- [ ] 正常匿名请求契约不变。

- [ ] seed/demo 在 production、非隔离 DB、缺确认时初始化前零写失败。
- [ ] seed guard 覆盖 symlink、parent symlink、hardlink 和目录逃逸。

## 九、时间、排序与 Analytics

## 签字规则

清单中的“通过”必须指向可复核证据，不接受“开发说已完成”“本地能打开”或“接口返回 200”作为单独结论。产品负责人确认业务口径与不做项；运营负责人确认后台字段、角色和发布流程；技术负责人确认契约、测试、运行资产和回滚；独立审计确认范围和高风险负例。一个人可以兼任多个职责，但不能省略对应视角。

若某项不适用，应写明原因，例如“本批无 schema 变化，因此 migration 不适用”“用户明确不要浏览器回归，且任务仅为本地静态补丁”。不适用不是空白，也不能用来跳过与实际风险相关的门禁。发现延期 P2 时记录影响、临时边界和下一步授权要求，不在当前小补丁中夹带实施。

最终状态只选一个：本地待审、代码可部署、已 push/tag、已上线、已回滚或受阻。若生产切换失败但已经安全回滚，应写“已回滚、生产安全”，不能把曾经短暂切换包装成已上线。若 Git 已完成但尚未部署，应写“已 push/tag、生产无影响”。准确状态比乐观措辞更重要。
